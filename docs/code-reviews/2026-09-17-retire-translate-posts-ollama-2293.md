# Code review: retire translate-posts.js's Ollama call, repurpose as a checker (ut-docs#2293)

**Repo / branch:** `ut-website` / `fix/2293-retire-translate-posts-ollama`
**Card:** ut-docs#2293 (follow-up to ut-docs#2291, which moved build-time
translation to the pipeline cycle's own model and retired the homelab Ollama
endpoint for that purpose)

## What

`scripts/translate-posts.js` still targeted the retired NAS Ollama endpoint
(`192.168.1.231:11434`, `qwen3:30b-a3b`, a Key Vault token lookup). Per the
card's own two options, chose **repurpose as a checker** over plain deletion:
the script's existing `verify()` function was already a pure, well-tested
structural-completeness check (headings/links/product-name/script), so the
network-calling generator code was stripped and `main()` rewired to walk
`src/content/blog/<locale>/` and check whatever translations already exist on
disk, skipping (not failing) any locale/post pair with no translation yet —
a missing translation is a legitimate, honest English fallback, not a defect.

## What shipped

- `scripts/translate-posts.js`: deleted `ask()`, `resolveToken()`, the
  Ollama endpoint/model constants, the Key Vault lookup, and the
  generate-and-retry loop. Added `checkTranslation(source, locale,
  translatedRaw)`, which parses an already-committed translated `.mdx`
  file's frontmatter/body the same way the old `main()` read a source file,
  then hands both sides to the unchanged `verify()`. `main()` now only
  reads and reports — it writes nothing.
- `scripts/translate-posts_test.mjs`: added 3 tests for `checkTranslation()`
  (real-file-shaped drop detection, a clean pass, and an untranslated-title
  catch read from real frontmatter), alongside the existing 6 `verify()`
  tests — 9/9 pass.
- `.github/workflows/ci.yml`: the `check-translate-posts` job now also runs
  `node scripts/translate-posts.js` itself against the real committed blog
  content, not just the isolated unit test — possible for the first time
  because the script no longer needs LAN access to the NAS.
- `README.md`, `ut-docs/reference/translation.md`, and a stale comment in
  `src/content.config.ts` updated to describe the new behavior.

## Independent review

Fresh-context Sonnet subagent (this is a `complexity:easy` card). Ran the
checker and the test suite directly rather than trusting the diff; mutation-
tested `checkTranslation()`'s wiring (swapped `body` for `frontmatter` when
building the `translated` object) and confirmed a real test failure, then
reverted and confirmed green again — proves the new tests aren't vacuous.
Confirmed via grep that no secret, token, or the hardcoded LAN IP survives
anywhere in live code (only in historical `docs/code-reviews/*.md` records,
correctly left alone).

**Findings, all fixed before this commit**: four other files carried
comments that were accurate before this change and became stale because of
it — `src/content.config.ts`'s `legal` collection comment ("only ever
reads/writes blog"), `src/pages/[...lang]/blog/[slug].astro` (two comments
describing translation as "generated" by the script "against the
self-hosted model"), `src/pages/[...lang]/legal/[slug].astro`,
`tests/legal-pages.spec.js`, and `site/i18n.js` (three comments attributing
untranslated legal-page/footer strings to "the homelab Ollama endpoint is
unreachable" — a mechanism that no longer exists at all, not merely
unreachable; the real reason is that the new translation workflow hasn't
been extended to the `legal` collection yet). All five corrected to
describe the current mechanism. Not fixed, deliberately: the existing
translated `.mdx` files' own frontmatter comment ("Generated by
scripts/translate-posts.js ... re-run rather than patching this file") is
now slightly inaccurate (the script is read-only) but is committed content,
not code, and rewriting already-published translated posts for a comment
nit is out of scope for this card.
