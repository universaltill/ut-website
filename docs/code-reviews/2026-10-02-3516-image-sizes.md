# 2026-10-02 — ut-docs#3516: PageSpeed follow-up, accurate image sizes

**Why:** the owner re-ran PageSpeed Insights on `/en-gb` after #3493. Every
category scored 100, but the report still suggested "Improve image delivery"
(~93 KiB on mobile, ~58 KiB on desktop).

**Shipped**
- `scripts/make-image-variants.sh` now generates a 480/640/768/1024/1280 WebP
  ladder per screenshot. It never upscales: rungs as wide as the original are
  skipped.
- `site/index.html`: every `srcset` lists the ladder. `sizes` now matches the
  measured layout:
  - phones: `100vw - 32px`;
  - 561–900px gallery: `50vw - 40px`;
  - desktop hero: `(min(100vw,1120px) - 128px) * 0.46` (was a fixed 480px).
- `tests/responsive-images.spec.js`:
  - adds PageSpeed's own emulation (412×1.75, 1350×1) and 768×1/2;
  - adds a new invariant: a picked candidate is at most 1.4× its drawn
    device-pixel width (the smallest rung is exempt).
- README updated.

**Accepted, not fixed:** mobile Lighthouse still estimates ~22–57 KiB under
"image delivery" for the hero. That insight compares the file with the
CSS-pixel box (377px) and ignores the emulated 1.75× DPR. The image is really
drawn at 660 device px, so obeying it would make the hero visibly soft on
modern phones. "Properly size images" accounts for DPR, and it is clean.

**Review:** independent Fable subagent, run in a separate worktree.
- TDD re-verified: the old markup gives 7 failed / 10 passed; the new markup
  gives 17 passed.
- Swept 24 viewports (320–2560) × DPR 1/1.5/1.75/2/3, plus RTL `/fa-ir`: zero
  blurry picks and zero oversized picks.
- Every variant's real pixel width equals its descriptor.
- No BLOCKER or MAJOR findings.
- MINOR, fixed:
  - stub review record;
  - the script could upscale a narrow original (now guarded);
  - a leftover bare block in the test loop.
- MINOR, accepted:
  - phone `sizes` assume a 16px gutter while the CSS is
    `clamp(1rem, 4vw, 2.4rem)`. The error is ≤2.5%, and no rung falls in the
    error band.
  - the smallest rung (480w) is 1.45× on DPR-1 desktops. Lighthouse desktop
    still passes (per-image waste is under its threshold). A 384w rung is
    optional and not done.

**Verified beyond tests:**
- Lighthouse 12 against a local build: "Properly size images" is gone on
  mobile and desktop, and desktop "image delivery" passes.
- Site guards pass: documented paths, brand assets, compliance claims, SWA
  config, CSP.
- Full Playwright suite: all pass.

**Verdict:** safe to merge. After deploy, re-run PageSpeed on the live site.
