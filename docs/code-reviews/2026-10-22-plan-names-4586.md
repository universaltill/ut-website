# Review — plan names guard (ut-docs#4586)

## Scope
ADR-0060 (2026-10-17 amendment) renamed the **Chain** plan to **Multi-location**
and **Enterprise** to **Enterprise and chains**. The card asks the website to
use the new names everywhere (AC: no page names a plan Chain or plain
Enterprise).

## Finding
The site carries no plan names today: no pricing page or comparison exists yet
(the generated pricing source #729 and the paid-shop pricing page #3934 have
not landed). A case-sensitive search of `site/`, `src/` and the blog in all five
locales finds no `Chain` or `Enterprise`, and no localised equivalents of a
plan table. The AC therefore holds already; there was no copy to rename.

## Change
So the AC keeps holding when the pricing page arrives, `scripts/guard-plan-names.sh`
fails CI on a retired plan name in `site/i18n.js`, `site/*.html`, `src/**/*.astro`
and `src/content/**/*.mdx`. It is case-sensitive (lower-case "supply chain" is
fine), accepts "Enterprise and chains", fails closed per surface, and takes a
same-line `plan-name:allow <reason>` (not honoured in `i18n.js`). The test
`guard-plan-names_test.sh` covers each surface, the escape hatch and fail-closed
behaviour, and runs in the `check-compliance-claims` CI job.

## Known gap
Localised plan names (tr/de/zh/fa) are not checked, because none exist yet. The
pricing-page card should add them to the pattern when it picks translations.

## Verification
`bash scripts/guard-plan-names_test.sh` — all assertions pass, including the real
tree.

## Independent review (Opus 5.5, fresh context; author Sonnet 5.5)
No blocking defects. Fixed: title-case "Enterprise and Chains" was rejected;
"Enterprise and chainsaw" was accepted (missing `\b`); tests added for both,
for a non-English `i18n.js` block, for an allow marker on another line and for
the marker in `.astro`; this section was empty.
Accepted, not fixed: the match is line-based, so a name wrapped across lines
or split by markup is missed (same gap the compliance guard documents);
capitalised prose such as "Enterprise customers" fails and needs a rewrite
(`i18n.js`) or the allow marker (html/astro/mdx) — the guard is a denylist, not
a copy reviewer. `site/nav.js`, `consent.js` and `src/lib/*.ts` are not scanned
(no plan copy there; `llms.txt` strings come from `i18n.js`).
