# Review: branded 404 page + `/downloads/` redirect (ut-docs#3809)

**Date:** 2026-10-07 · **Built by:** Claude Opus 5.5 (lane:local) · **Reviewed by:** Claude Fable 5.1 (independent subagent, separate worktree)

## What shipped

Search Console reported `https://www.universaltill.com/downloads/` as 404, and
every unknown URL showed Azure's unbranded "Azure Static Web Apps - 404" page.

- `site/404.html`: branded page (site header/footer, message, home + download
  buttons), `noindex`, no canonical/hreflang, no language pill. One file for
  every locale: `i18n.js` picks the locale from the URL (else the remembered or
  browser language) and moves its `/en-gb` links to that locale.
- `staticwebapp.config.json`: `responseOverrides.404 → rewrite /404.html`;
  `/downloads` and `/downloads/` 301 to `/en-gb/download`.
- `scripts/check-swa-config.js`: allows exactly that one override (the old 401
  redirect stays rejected) and checks the file exists.
- `scripts/serve-site.js`: emulates the override for the Playwright suite.
- `deploy.yml` live check: `/downloads/` 301, and an unknown URL answers 404
  with the branded page.
- Keys `meta.nf.title`, `nf.title|lede|home|download` in all five locales.
- `tests/not-found.spec.js`: 14 tests.

## Follow-up: deploy refused a duplicate route

The first deploy after merging ut-website#56 failed before upload: Azure reported
"A rule was already processed with a duplicate route /downloads/". It ignores the
trailing slash when comparing routes, and the route `/downloads` already answers
`/downloads/`. `serve-site.js` matched routes exactly, so the suite couldn't
see this. The live site was unchanged, because the upload was refused.

Fix: drop `/downloads/`. `check-swa-config.js` fails on routes that differ only
by a trailing slash (`methods` are part of the key, as Azure allows one route
per method set). It accepts a config path, and the new
`check-swa-config_test.sh` (run in CI) covers the guard; a mutant with the guard
disabled fails it. `serve-site.js` now matches a plain route with or without the
trailing slash, as Azure does.

Independent Fable review of the follow-up: safe to merge. It confirmed from the
SWA docs that folder-path routes match both forms. Its two low findings (methods
in the key, no negative test) are fixed. Accepted: serve-site's slash equivalence
also applies to file routes (`/index.html/`); Azure's behaviour there is
undocumented and nothing requests such a path. Full suite: 269 passed.
